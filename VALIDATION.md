# Integration validation

The local integration checks passed: 11 fusion/policy tests, 14 safety tests, five perception converter/geometry tests, and 16 viewer unit tests. Node 24.22.2 typechecking and the production build also passed. Python checks used the modules' existing isolated environments: Python 3.12.3, NumPy 2.5.4, PyTorch 2.15.0+cu132 for fusion, pandas 3.1.0 for safety, and PyArrow 26.0.0/Pillow 13.0.0 for perception.

The two new safety exports rerun actual recorded matrix cases with the shared root simulator/EKF. Their outcome, duration, minimum clearance and localization RMSE match the saved rows. The exporter records the matrix and replay hashes in `results/replay_integration.json`. Optional recording adds no random draws or control actions. Viewer tests parse those exports, and the native browser checks the normal/failure loader, playback, scrubbing, point counts, layers, exact collision terminal frame, fault state and terminal RMSE.

Three native Windows rendering groups completed on RTX 3080 / ANGLE D3D11, Chromium 156.0.8078.4, driver 621.01. `viz/results/native-gpu/bench.json` preserves every frame interval, actual renderer and physical GPU information, UTC group windows, scene hash/world and source/bundle hashes. Final UI-only checks and refreshed screenshots are in `viz/results/native-ui-final`; a later End-key/HUD fix did not repeat the valid performance groups.

The full official SKU archive was downloaded and hashed, all splits converted, and actual training-loader verification recorded in `perception/results/sku110k_full_provenance.json` and `dataset_verification.json`. YOLO11s completed all 100 epochs with 8,216 usable training images and 1,207,996 boxes, batch 8, 640-pixel input and seed 0 on RTX 3080. `full_training_epochs.csv` preserves the 100 native rows. `full_training_args.yaml` and `training_gpu_snapshot.json` record the actual configuration, source hashes and GPU evidence.

The original training process then hit a metadata assertion because Ultralytics 8.4.196 emits a final-best-validation callback labeled 101. The raw extra event, original exit 1 and exact training source 5238181 / SHA-256 `24ac8f2b5a847f1d3d8cfc0991da020eefddd00e381804d7fa56e60eba333044` remain recorded. The reviewed finalizer at source 7be44f1 checks both stripped checkpoints' 100-row `train_results` against every native CSV column, preserves the failed metadata and performs the already planned independent best-checkpoint validation without training again. It exited 0. The overlapping callback-101 timer is separate from the 100 training-epoch windows.

That final validation covered all 588 images / 90,968 boxes, with batch 8, eight workers and cache off: precision 0.9111203555, recall 0.8739226981, mAP50 0.9281214546 and mAP50–95 0.5781538475. Its results dictionary and per-class precision/recall/AP-by-IoU arrays are preserved in `perception/results/train_full_3080.json`. This is distinct from the internal per-epoch validation loader (batch 16, workers 16, RAM cache). The one official train RAM-cache attempt was rejected by the unchanged gate and was not retried.

The same best-weight hash was used for ONNX export. Raw PyTorch/ORT outputs on one seed-0 synthetic tensor passed allclose at 0.001 with max absolute error 0.000152587890625. The CPU raw-forward benchmark has 50 samples per backend after five warmups, batch 1 and four threads: ORT p50/p95 52.5/53.9 ms, PyTorch 77.4/83.6 ms. The separate 20-image ONNX end-to-end observations use actual library defaults (ORT intra/inter-op 0/0, Torch threads 2), with p50/p95 66.2/137.2 ms. All raw timings, detections, model hashes and protocol scopes are in `perception/results/onnx_bench_full.json`. Staged model bytes and existing upstream license/attribution are identified in `perception/results/model_artifacts.json`.

The root workflow runs CPU tests, an actual 30-second ROS 2 loop and explicitly labeled SwiftShader browser correctness. The retained 180-second local ROS run and its environment/model provenance are in `results/VALIDATION.md`. Source histories remain intact; all four original HEADs are ancestors, recorded in `results/source_history.json`.
